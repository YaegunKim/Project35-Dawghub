# MapPage

The most complex screen in the app. A single Leaflet map with 6 layers (each with a visibility toggle + per-category settings modal), GPS/compass location tracking, campus boundary display, and dorm/class markers — all inside `src/pages/map/MapPage.tsx` (~1200 lines). It is supported by 4 popup types (`src/pages/map/popups/*.tsx`), a React→Leaflet mount utility (`reactPopup.tsx`), and a layer-settings localStorage hook (`src/lib/mapLayerPrefs.ts`).

## Purpose

Overlays live buses, library/dining/gym locations + hours, and dorm/academic-building locations on the UGA campus map in one view, and automatically highlights the user's current location, their dorm, and the buildings where they have classes on their schedule.

## Layer structure

Pressing the circular "Layers" button at top-right (`S.LayersButton`, FontAwesome layer-group icon) opens a **drawer that slides in from the right** (`S.Drawer`, `drawerOpen` state). The 6 rows inside the drawer each correspond to an `L.LayerGroup` (`layersRef.current`), and each row shows a summary of its current settings (e.g. "All routes", "3 selected", "Not set") as a subtitle. Pressing a row opens that category's dedicated **settings modal** — library/dining/gym/academics reuse the shared `LayerChecklistModal` component, while bus and housing have different UI and are written inline. The "Show this layer" switch at the top of each modal replaces the old chip on/off toggle (`toggleLayer(key)`, `map.addLayer`/`removeLayer`). (Even earlier this was an always-on horizontal scrolling legend bar at the top, but since no other tab has a fixed top bar the inconsistency feedback moved it to a top-right button + panel, and this iteration evolved that panel one step further into a drawer + modal — the principle of not having a fixed top-bar UI pattern anywhere in the app still holds.)

- **bus**: a group bundling `routesLayer` (route polylines) + `stopsLayer` (stop circles) + `liveBusLayer` (live bus triangle icons, rotated to heading). Polls every 8 seconds (`BUS_POLL_INTERVAL_MS`); position changes move smoothly via a 6-second (`BUS_ANIMATION_MS`) easing animation (`animateMarkerTo`). The modal lets you choose a mode (3 radios: **running routes only / all routes / pick manually**), and "pick manually" adds a route-name checklist. Settings are saved to `localStorage` (`dawghub:map:bus`, `useBusLayerPrefs`). **Stops are filtered along with routes** — each stop entry in the Passio `getStops` response carries a `routeId`/`routeName` (a physical location belongs to one route rather than being duplicated across several), exposed as `PassioStop.routeName`, and `applyBusFilter` uses the same `shouldShowRoute(name)` check as the route polylines to toggle the stop markers too (`stopMarkers` tracking array).
- **library**: the 9 buildings defined in `LIBRARY_BUILDING_NAMES`, book-open-reader FontAwesome icon. Popup is `MapInfoPopup` + today's hours (LibCal). The modal picks which buildings to show via a per-building checklist (`useFavorites('dawghub:map:library')`, all-unchecked = "show all").
- **dining**: the 6 in `DINING_BUILDING_NAMES`, utensils icon. Popup is `MapDiningPopup` (today's hours + a live query of the current meal's menu via the `getDiningMenu` Lambda + a `/dining/:hall` link). Checklist follows the same pattern as library (`dawghub:map:dining`).
- **gym**: the 2 in `GYM_BUILDING_NAMES` (Ramsey Center, Pound Hall), dumbbell icon. Pound Hall's popup label is hardcoded to "Pound Hall & Wheeler Gym" (two buildings sharing one facility). Checklist follows the same pattern (`dawghub:map:gym`).
- **housing**: every building with `buildingUse === 'Housing'` shown as a radius-2px `circleMarker` (dot). Click opens `MapDormPopup` — a "Set as my dorm" toggle (the existing mechanism is unchanged). In the modal, instead of a checklist there is a search input (datalist autocomplete) + a save button to set the same `myDormBuilding` — the designated dorm is shown as a house-shaped (`faHouse`) marker instead of a dot (`HOUSE_ICON`, `refreshDormHighlight`).
- **academics**: it no longer shows all 318 academic buildings; markers are created **only for buildings matched against my schedule (`ClassEntry.location`)** (`entriesByBuilding`). The modal's checklist picks which of those to actually show on the map (default is show all) — the result is saved to `MapPreference.myAcademicBuildings` (Amplify). Click opens `MapAcademicPopup` — the list of my classes that meet in that building (read-only).

Common: icon-style markers registered in `zoomAwareMarkers` (library/dining/gym) switch to the full icon when zoomed in (`BASE_ZOOM=15` or above) and to `dotIcon` when zoomed out (`updateMarkerDetail`, `zoomend` event). Library/dining/gym/academics/bus-route markers are not added to their layer immediately on creation; they are held in a `{name, marker}` tracking array and the `applyXFilter(selected)` function decides actual visibility based on `layer.hasLayer(marker)` (re-invoked on every checklist change).

### Why storage is split (account vs localStorage)

Bus mode / selected routes and the selected library/dining/gym buildings are pure display settings that can change often, so they are saved to `localStorage` (`dawghub:map:bus/library/dining/gym`) — sending a GraphQL mutation every time would only add RPC load, and cross-device sync is not essential. Conversely, "my dorm" and "my academic buildings" are low-frequency settings closer to "who I am", so they stay in the existing `MapPreference` Amplify model (`myDormBuilding`, `myAcademicBuildings`) — the fields were already in the schema (no migration needed).

## Data sources

- **Live bus position / routes / stops**: Passio GO (`src/lib/passio.ts`, `fetchUgaBuses` / `fetchUgaRoutesAndStops`) — UGA system id `3994`, CORS is open so the frontend polls directly.
- **Building coordinates + use (BuildingUse)**: UGA ArcGIS (OUA) (`src/lib/ugaBuildings.ts`, `fetchUgaBuildings`) — the library/dining/gym/housing/academics layers are all filtered from this. `MANUAL_BUILDINGS` adds 3 new buildings not in the GIS (Hillside Dining Commons, The Niche, Village Summit Dining Commons) with estimated coordinates.
- **Library hours today**: LibCal (`src/lib/libraryHours.ts`, used in the library popup).
- **Gym hours today**: `src/lib/gymHours.ts`, hardcoded by manually parsing the Rec Sports PDF (needs a manual update each semester — see README "External data sources" for details).
- **Dining menu**: the `getDiningMenu` Lambda query that proxies Nutrislice (queried live each time a dining popup opens).
- **Campus boundary polygon**: `src/lib/campusBoundary.ts` — a static coordinate array taken from OpenStreetMap relation 21071510 (ODbL). Shown only as a dashed polygon (`interactive: false`), no click/interaction.
- **My dorm**: the `myDormBuilding` field of the `MapPreference` model (`src/lib/mapPreferences.ts`, a singleton "create if missing" caching wrapper).
- **Buildings where I have classes**: reads all `ClassEntry` records (`client.models.ClassEntry.list()`) and matches each `location` string against ArcGIS building names via `findBuildingByName` → builds a per-building class list (`entriesByBuilding`).

## Things to know

- **GPS/compass permission must be started by a user gesture**: location tracking only starts by clicking the bottom-left 📍 button (`LocateControl`) (`startTracking`). On iOS Safari, `DeviceOrientationEvent.requestPermission()` must be called inside a user-gesture handler for the permission prompt to appear, so moving this request out of the button-click callback (e.g. into an auto-running `useEffect`) makes it fail silently on iOS. If permission is denied/unsupported, only the GPS coordinate is shown, with no compass heading cone.
- **The compass heading source differs per platform**: iOS uses `webkitCompassHeading` (non-standard, preferred); other browsers use the `alpha` value from `deviceorientationabsolute`/`deviceorientation`, converted as `(360 - alpha) % 360`. Both listeners are registered and whichever produces a value is used.
- **Setting a dorm = clicking a map dot or the layer modal, both the same field**: clicking a dorm dot on the map and toggling in `MapDormPopup`, or setting it via the search input in the layer drawer → housing modal — both save the same value to Amplify via `updateMapPreference({ myDormBuilding })` (unified through `mapActionsRef.current.setMyDorm`). The set building turns from a dot into a house-shaped marker (`HOUSE_ICON`) (`refreshDormHighlight`). Only one can be set at a time (designating a new dorm auto-clears the previous one).
- **Academic buildings get markers only for "buildings where I have classes", and a checklist picks which of those to show**: marker creation itself is automatic (only buildings present in `entriesByBuilding`, the result of matching `ClassEntry.location`); whether to actually display each on screen is chosen via the checklist in the layer drawer → academics modal (default shows all candidates, saved to `MapPreference.myAcademicBuildings`). Since every building that has a marker means "a building where I have classes", they are always highlighted purple (`MY_ACADEMIC_COLOR`) — there is no separate grey/purple distinction.
- **Dot markers are very small at radius 2px (`BUILDING_DOT_RADIUS`)**: barely visible until you zoom in, just enough to register a click — this is intended (code comment: "barely visible until you zoom in, just enough to click"). Unlike the icon-style layers (library/dining/gym), the icon does not grow with zoom; the radius is always the same.
- **Popups render real React components**: `bindReactPopup` (`reactPopup.tsx`) mounts them onto a detached DOM node with `createRoot().render()` and passes that to `marker.bindPopup()`. For cases where popup content changes asynchronously after it opens (like the dining popup), a `ResizeObserver` detects content-size changes and calls `popup.update()` — without this observer the popup shows clipped content after the menu loads.
- **Bus markers are reused by ID**: markers are not recreated every poll; they are cached by id in the `busMarkers` Map, and only buses that disappeared are removed from the layer — that is why positions animate continuously with no flicker.
- **Map/subscription teardown is all handled in `useEffect` cleanup**: `watchId` clear, removal of both kinds of orientation listener, `setInterval` clear, and `map.remove()` — so leaving and re-entering the page never leaves duplicate polling/listeners behind.
- **The zoom-level display control** shows not the actual Leaflet zoom value but the icon scale (%) computed by `iconScaleForZoom()` — when debugging, do not mistake the number at bottom-right of the map for the "zoom level".
