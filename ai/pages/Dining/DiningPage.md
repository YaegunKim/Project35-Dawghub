# DiningPage (`/dining`)

## 목적

UGA 학식당 6곳을 카드 목록으로 보여주고, 각 카드에 오늘 해당 끼니(아침/점심/저녁)의 메뉴 미리보기를 띄운다. 즐겨찾기한 학식당은 목록 맨 위로 정렬된다.

## 데이터 소스

- **메뉴**: [Nutrislice](https://uga.nutrislice.com)(`uga.api.nutrislice.com`)를 직접 호출하는 게 아니라, CORS가 막혀 있어서 Amplify 커스텀 쿼리 `getDiningMenu`(`amplify/data/resource.ts`, 핸들러는 `amplify/data/get-dining-menu/handler.ts`)가 서버에서 대신 호출해 프록시한다. `DiningHallCard`가 학식당(`hall`)·끼니(`mealType`)별로 `client.queries.getDiningMenu({ hallSlug, mealType })`를 각각 호출 — 카드 6개면 쿼리 6개가 독립적으로 나간다(배칭/캐싱 없음).
- **운영시간**: 실시간 API가 없어 `src/lib/diningHours.ts`에 요일별 시간을 하드코딩(dining.uga.edu 페이지를 손으로 옮겨 적음). 학기 중 UGA가 시간을 바꾸면 수동 갱신 필요.
- **학식당 6곳**(`src/lib/dining.ts`의 `DINING_HALLS`, 카드 표시 순서 기본값): `bolton`, `hillside`, `oglethorpe`, `snelling`, `niche`, `villageSummit`. 이름은 `dining.halls.*`(i18n)로 표시.

## 알아둘 것

- **끼니(mealType) 판정은 진입 시점 1회만**: `DiningPage`가 `useState(() => getCurrentMealType())`로 마운트 시 한 번만 계산(10시 이전 아침/15시 이전 점심/그 외 저녁). 페이지를 계속 띄워둔 채로 시간대가 바뀌어도 재계산 안 됨 — 새로고침해야 반영.
- **카드 안 끼니 라벨 옆에 그 끼니 시간도 회색으로 표시**: `DiningHallCard`의 `S.MenuRow`(`t('dining.mealTypes.…')` 빨간 라벨 + `getDiningMealHoursToday(hall, mealType)` 회색 시간). 상세 페이지 끼니 탭과 같은 데이터 소스(`src/lib/diningHours.ts`의 `DINING_MEAL_HOURS`)를 쓰고, 괄호 안 캐비엇(예: Niche의 "HSC residents only")은 `splitHoursNote`로 잘라내고 시간만 보여줌 — 이 한 줄짜리 라벨에는 공간이 없어서 상세 페이지처럼 별도 줄로 안 보여줌.
- **즐겨찾기**: `useFavorites('dawghub:dining:favorites')`로 localStorage에 저장 (Amplify 모델 아님, 로그인과 무관). `sortHallsByFavorite`가 즐겨찾기만 앞으로 당기고 나머지는 원래 순서 유지하는 안정 정렬은 아님(단순 boolean 비교 sort).
- **카드 안 섹션 순서 + 핀 표시가 고정(핀) 상태를 따름**: 상세 페이지(`DiningHallDetailPage`)에서 압정으로 고정한 섹션(예: "Entrees")은 `dawghub:dining:pinnedSections`를 공유해서 이 카드 미리보기에서도 항상 맨 위로 오고(`sortSectionsByPinned`, 상세는 [[DiningHallDetailPage]] 참고), 섹션 제목 옆에 작은 압정 아이콘(`S.PinIndicator`)도 같이 뜸 — 다만 카드 쪽 아이콘은 눌러서 껐다 켰다 할 수 있는 버튼이 아니라 상태만 보여주는 읽기 전용 표시(고정/해제는 상세 페이지에서만 가능).
- **메뉴 중복 항목 제거는 진짜 그룹핑이 아님**: Nutrislice 응답에 station_id/is_section_title이 항상 비어 있어 실제 스테이션 구분이 불가능 — Lambda 쪽에서 이름 기준으로 중복만 제거하고(`seenNames`), 조미료/음료/디저트류 키워드(`SECONDARY_SECTION_KEYWORDS`)를 뒤로 미루는 방식으로 우선순위만 흉내낸 것. `groupMenuItemsBySection`(`src/lib/dining.ts`)는 백엔드가 이미 정렬해 준 순서를 그대로 Map에 담아 섹션별로 묶기만 함.
- **카드 안 메뉴 미리보기는 섹션당 최대 4개**(`MAX_PREVIEW_ITEMS`), 초과분은 "+N개 더"로 표시. 전체 메뉴는 상세 페이지(`/dining/:hall`, `DiningHallDetailPage`)에서 확인.
- **식단/알레르기 태그**(`DietaryTags.tsx`)는 `DIETARY_ICON_URLS`/`ALLERGEN_ICON_URLS`에 매핑이 있는 태그만 렌더링 — Nutrislice가 내려주는 아이콘 슬러그 중 매핑 없는 것(예: `taste-of-home`)은 Lambda 단에서 이미 걸러짐.
- **식단/알레르기 태그로 메뉴 자체를 필터링**: `PageTitle` 옆 톱니바퀴 버튼(`S.TitleRow`)을 누르면 `TagSettingsModal`이 뜸 — 식단 5종/알레르기 9종을 두 섹션으로 나눠 아이콘+이름을 보여주고, 각 태그마다 **표시(Show) / 숨김(Hide)** 2단 세그먼트(`S.Segment`, 둘 다 한 줄에 알약 모양으로 보여서 바로 클릭 선택)가 있음. "숨김"으로 설정한 태그들은 OR로 결합(그중 하나라도 있는 아이템은 빠짐) — 여러 태그를 동시에 숨길 수 있음. **"이것만"(해당 태그를 가진 아이템만 남기는 AND 필터) 옵션은 의도적으로 뺐음**: Nutrislice 태깅이 "이 요리는 할랄" 같이 애매한 경우에만 태그를 붙이고 오렌지주스처럼 명백히 안전한 항목엔 태그 자체를 안 붙이는 경우가 많아서, "할랄=이것만"으로 필터링하면 실제로 문제없는 무태그 항목까지 같이 사라져서 오히려 "이 목록이 전부 안전하다"는 잘못된 확신을 줄 수 있었음(태깅 데이터 자체의 한계라 프론트에서 고칠 수 없는 문제 — 이전 커밋 히스토리에 3단계 버전이 남아있음). 상태는 `dawghub:dining:tagFilters`(`localStorage`, `src/pages/dining/tagFilters.ts`의 `useTagFilters()`, `show`가 기본값이라 `hide`로 오버라이드된 것만 저장)에 저장되고, 필터링 함수 `filterItemsByTagState`(`src/lib/dining.ts`)가 섹션으로 묶기 전에 메뉴 아이템 배열 자체를 걸러내므로 이 목록 카드와 상세 페이지(`DiningHallDetailPage`) 둘 다에 동일하게 적용됨(설정 버튼은 이 페이지에만 있지만 효과는 전역). 필터로 다 걸러지면 `dining.noMatch`로 "메뉴 없음"과 구분해서 표시. 모달 헤더의 "초기화" 버튼(활성 필터가 있을 때만 노출)으로 한 번에 리셋 가능.
- **`useTagFilters`는 모듈 레벨 외부 스토어(`useSyncExternalStore`) 기반**: 처음엔 컴포넌트마다 독립된 `useState`로 구현했었는데, `TagSettingsModal`(설정 버튼 눌러서 뜸)과 여러 개의 `DiningHallCard`(목록에 6개)가 전부 `DiningPage`에 동시에 마운트돼 있다 보니 — 모달에서 필터를 바꿔도 카드는 자기 마운트 시점에 한 번 읽은 값을 그대로 들고 있어서 즉시 반영이 안 되는 문제가 있었음(핀 고정 기능도 처음엔 같은 문제가 있었지만 그쪽은 한 화면에 동시에 안 뜨는 페이지라 눈에 안 띄었을 뿐). 지금은 `cachedFilters` 모듈 변수 + `listeners` Set으로 모든 `useTagFilters()` 호출부가 하나의 소스를 구독해서, 어디서 바꾸든 그 순간 전부 리렌더됨.
- **필터 변경 시 잠깐 스켈레톤을 보여주는 건 진짜 로딩이 아니라 의도적인 연출**: 필터링/그룹핑은 전부 동기 계산(`useMemo`)이라 원래는 버튼 누르자마자 목록이 순간이동하듯 바뀌는데, 그게 부자연스럽다는 피드백이 있어서 `useTransitionFlash(tagFilters, 300)`(`src/lib/useTransitionFlash.ts`, 범용 훅)로 필터 값이 바뀔 때마다 300ms짜리 "가짜 로딩"을 흉내냄 — 버튼 상태 자체는 즉시 바뀌고, 메뉴 목록만 기존 네트워크 로딩 스켈레톤(`isLoading || isFilterTransitioning`)을 잠깐 다시 보여준 뒤 새 결과로 정착함. 마운트 시 최초 1회는 안 뜨도록 `useRef`로 첫 렌더를 건너뜀. `DiningHallDetailPage`도 동일 패턴.
- Hillside/Niche/Village Summit의 지도 좌표는 공식 GIS에 없어 수동 조사한 값을 쓰는데, 이건 지도 표시 관련 이슈라 `ai/pages/Map/MapPage.md`에서 다룸 — 이 목록 페이지 자체와는 무관.
- **지금 문 닫았으면 "다음 여는 시간" 표시**: `isDiningHallOpenNow(hall)`/`getNextDiningOpen(hall)`(`src/lib/diningHours.ts`)로 판정, 카드 헤더(`S.NextOpen`)와 상세 페이지 헤더에 각각 표시. **일별 통합 시간표(`DINING_HOURS`)와 끼니별 시간표(`DINING_MEAL_HOURS`) 둘 다 같이 확인**해야 정확함 — 어느 한쪽만 쓰면 구멍이 생김: 끼니별 데이터만 보면 Hillside의 "심야(late night, 밤 10시~새벽 2시)" 시간대는 아침/점심/저녁 어디에도 안 걸려서 실제로는 영업 중인데 닫은 걸로 잘못 판정되고, 반대로 통합 시간표만 보면 Niche는 "7:00am–2:30pm"(저녁은 괄호 안 메모로만 언급)이라 오후 5~7시 저녁 시간에 실제로 여는데도 못 잡아냄(그리고 애초에 The Niche는 점심 끝나고 저녁 시작 전인 오후 2:30~5시엔 진짜로 닫혀있는 갭이 있음 — 통합 시간표만 보면 이 갭 자체를 못 잡아서 "하루 종일 열려있다"고 착각하기도 함). 그래서 `allRangesForDay`가 끼니별 3개 + 통합 1개, 총 4개 구간을 합쳐서 "지금이 그중 하나에 속하나"로 판정. 자정 넘어가는 구간(예: "7:00am–2:00am")은 종료 시각에 +24시간 해서 계산하고, 어제 날짜 구간이 자정을 넘어 오늘 새벽까지 이어지는지도 별도 체크. `getNextDiningOpen`은 최대 7일치를 앞으로 훑어서 가장 가까운 미래 시작 시각을 찾음 — "오늘 5:00pm"/"내일 7:00am"/"{{요일}} 7:00am"(요일은 시간표 페이지의 `schedule.days.*` i18n 재사용) 형태로 표시.
- **제목 오른쪽에 오늘 날짜 뱃지**: `S.TitleGroup`(가로 flex, `PageTitle`과 같은 줄)에 📅 이모지 + `formatTodayLabel(t, i18n.language)`(`src/lib/dining.ts`) 결과를 흰색 알약 뱃지(`S.TodayDate`)로 표시 — "📅 September 1 · Tuesday" / "📅 9월 1일 화요일" 형태. 월/일 부분은 `Intl.DateTimeFormat(locale, {month:'long', day:'numeric'})`로 로케일에 맞게 포맷하고, 요일은 "다음 여는 시간"과 동일하게 `schedule.days.*` i18n을 재사용(새 요일 문자열 세트를 따로 안 만듦, `WEEKDAY_I18N_KEYS`를 export해서 공유). **뱃지 배경은 의도적으로 테마 변수가 아니라 `brand.white`/`brand.black` 고정 색**(다크모드에서도 항상 흰 배경 + 검은 텍스트) — "흰색 뱃지"로 명시적으로 요청받은 디자인이라 다른 컴포넌트들의 "색상은 항상 토큰에서" 원칙의 의도적 예외. 처음엔 제목 아래 줄에 회색 텍스트로만 작게 넣었었는데, 뱃지+이모지로 바뀌면서 제목과 같은 줄(가로)로 배치가 바뀜. 이 앱은 고정 상단바가 없고 각 페이지 제목이 스크롤되는 콘텐츠의 일부라는 CLAUDE.md의 의도적 결정 때문에, 이건 "탑바"가 아니라 학식 탭 `PageTitle` 영역의 뱃지일 뿐 — 다른 탭에는 없음(요청 범위가 학식 탭으로 한정됨).
- **카드 디자인 폴리시**: 즐겨찾기 별 아이콘을 텍스트 글리프(★/☆)에서 FontAwesome `faStar`로 교체(다른 곳과 아이콘 일관성 + `IconButton`의 기존 `aria-pressed` 색상 전환 그대로 재사용, outline 스타일 아이콘 패키지가 없어서 채워진 별을 색상으로만 구분 — 즐겨찾기 안 된 상태도 무채색 채워진 별). 끼니+시간 줄(`S.MenuRow`)을 평범한 텍스트에서 알약 모양 칩으로, 섹션 제목 옆에 학식 카테고리색(`category.dining`) 점을 추가해서 스캔하기 쉽게, 카드 그림자/모서리를 좀 더 또렷하게(`shadow.md`/`radius.lg`)해서 카드 하나하나가 더 도드라지도록 함.
- **학식당 이름 옆 영업 중/영업 종료 뱃지**: `isDiningHallOpenNow(hall)`(이미 "다음 여는 시간" 기능에서 쓰던 함수, `src/lib/diningHours.ts`)를 그대로 재사용해서 `S.StatusBadge`(색이 있는 점 + 텍스트, 알약 배경)로 표시 — 영업 중은 초록(`state.success`/`successSoft`), 종료는 빨강(`state.danger`/`dangerSoft`, 기존 태그 필터 "숨김" 뱃지와 같은 색). `state.success`/`successSoft`는 이 기능 때문에 `colors.ts`에 새로 추가한 토큰(기존엔 `danger` 계열만 있었음). 뱃지 디자인은 "색만으로 상태를 표현하지 말고 점+텍스트를 같이 쓸 것", "알약 모양이 상태 뱃지에 제일 흔함" 같은 일반적인 뱃지 UI 가이드라인을 참고해서 정함.
- **메뉴 미리보기를 펼치고 접는 아코디언으로 변경**: 예전엔 카드 안 메뉴 섹션이 항상 펼쳐져 있었는데, 학식당 6개를 다 펼쳐두면 목록이 너무 길어져서 기본값을 **접힌 상태**로 바꿈. 카드 맨 아래 "메뉴 보기"/"메뉴 접기" 버튼(`S.ToggleRow`, 위아래로 뒤집히는 셰브런 아이콘 `S.ToggleChevron`)을 눌러야 펼쳐짐 — 아코디언 UI 일반 가이드라인(라벨 뒤에 셰브런, 상태 바뀔 때 아이콘도 회전, 탭하기 편한 큰 영역)을 참고. 카드 전체는 여전히 클릭하면 상세 페이지로 이동하므로, 이 토글 버튼만 `stopPropagation()`으로 그 동작을 막음(즐겨찾기 별 버튼과 동일한 패턴). 펼침 애니메이션은 JS로 높이를 측정하지 않고 `grid-template-rows: 0fr → 1fr` CSS 트릭(`S.ExpandableRegion`/`S.ExpandableInner`)으로 처리 — 콘텐츠 높이가 로딩 상태에 따라 계속 바뀌어도(스켈레톤 → 실제 메뉴) 매번 재측정할 필요가 없음. 데이터 자체는 접혀 있어도 그대로 `useQuery`가 계속 불러오므로(펼칠 때 로딩 깜빡임 없이 바로 보임), 이건 순수 UI 표시 문제지 데이터 페칭 타이밍을 바꾼 게 아님.
